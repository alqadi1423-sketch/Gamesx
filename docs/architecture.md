# البنية التقنية (للمطورين)

JavaScript عادي بدون إطار عمل ولا أداة بناء: ملفات تنقرا مباشرة في المتصفح، وكلها تتشارك متغيرات عامة (`S` و`GAMES` و`HELP`…). الفكرة مأخوذة من boardgame.io: **اللعبة دوال بسيطة تاخذ الحالة وترجع حالة جديدة، والمحرك يتكفل بالباقي** (الأدوار، الشاشات، الأونلاين، البوتات، الأسرار).

قبل ما تضيف لعبة اقرا [game-checklist.md](game-checklist.md).

### ترتيب التحميل

1. **أول شاشة:**
   - `style.css` و`perf.css`؛
   - ثم السكربتات: `capacitor.js`، `emoji.js`، `core.js`، `seal.js`، `views.js`، `net.js`، `help.js`، `transport-ws.js`، `transport-near.js`؛
   - ثم `boot.js`، اللي يرسم الصفحة الرئيسية على طول.
2. **بعد أول رسمة** (`loadGames` في `core.js`: إطار رسم ثم مهمة، أو ثانية ونص كحد أقصى للصفحة المفتوحة بالخلفية):
   - محتوى `<template id="later-css">` ينضاف **قبل** `perf.css`؛
   - ومحتوى `<template id="later-js">` ينضاف بالترتيب (`async=false`): `dict.js`، ثم ملفات الألعاب، ثم `kit-hara.js`، ثم `n-hide.js` و`n-taqiya.js`، وآخر شي `bots.js`.
3. **قبل ما تخلص الألعاب** (`GREADY=false`):
   - الصفحة الرئيسية تعرض الأسماء والأيقونات المحفوظة من آخر زيارة (`GMETA` في `alaabna.meta`).
   - أي ضغطة تحتاج الألعاب تستنى (`whenGames`) وتطلع «نجهّز الألعاب…».
4. **تحت الاختبار الآلي** (`navigator.webdriver`): الألعاب تنحمّل على طول، فحدث `load` يعني إن كل الألعاب موجودة.

**لعبة جديدة** تضيف سطر `<link>` داخل `later-css` وسطر `<script>` داخل `later-js` قبل `bots.js`. وكل الروابط فيها `?v=<رقم>` يغيّره `tools/bump.sh`.

## 2. واجهة اللعبة: `GAMES.<id>`

كل لعبة كائن في `GAMES`. الحالة العامة اسمها `d` (تنرسل للكل أونلاين، فلازم تكون JSON)، و`s` رقم المقعد (0 إلى n−1)، والمقعد `s` يلعبه الدور (اللون) `d.pl[s]`.

### الأساس

| الحقل | النوع | الوصف |
|---|---|---|
| `name`, `icon`, `cat` | نص، SVG، نص | الاسم والأيقونة والقسم (`board`, `cards`, `dice`, `party`, `quiz`, `words`, `mind`, `puzzle`, `speed`, `fight`, `sport`) |
| `minP` / `maxP` | رقم | أقل وأكثر عدد لاعبين (الافتراضي 2 و8) |
| `init(n)` | ← `d` | الحالة الأولى لعدد `n` من اللاعبين. المحرك يضيف لها `gid`, `st`, `turn`, `pl`, `out`, `win` (و`tm` مع الفرق) |
| `start(d, base)` | ← `d` | اختياري: يعدّل الحالة بعد ما يحط المحرك مفاتيحه (مثلًا الشطرنج يبدأ دايمًا بالمقعد 0) |
| `render(d, ctx)` | ← HTML | يرسم اللوحة. `ctx.v` المقعد اللي يشوف، و`ctx.my` هل يقدر يلعب الحين، و`ctx.local` جوال واحد، و`ctx.priv` الأجزاء الخاصة |
| `click(a, i, d, ctx)` | | يستقبل ضغطة على `data-ga="a"` و`data-i="i"`، ويستدعي `act(nd)` بالحالة الجديدة أو `setPriv(role, p)` |
| `status(d, ctx)` | ← HTML | اختياري: سطر الحالة (الافتراضي «دورك» أو «دور فلان») |
| `points(d)` | ← مصفوفة | اختياري: النقاط تحت كل لاعب في الشريط |
| `winText(d)` / `winExtra(d, ctx)` | ← نص | اختياري: عنوان الفوز ونص إضافي في النتيجة |
| `onTimeout(d)` | ← `d` | وش يصير إذا خلص وقت الدور (الافتراضي: الدور للي بعده) |
| `noTimer` | `true` | اللعبة لها ساعتها الخاصة، وما تستخدم وقت الدور العام |
| `teams` | `'native'` أو `'none'` | `native`: فرقها من قوانينها (البلوت، الشطرنج…). `none`: كل واحد لحاله. بدونه: المحرك يسوي الفرق |
| `teamsOk(sizes, n)` | ← `true/false` | للألعاب `native`: هل تقسيم الفرق هذا ينفع |
| `viewer(d, priv)` / `coverMsg(d)` | | على جوال واحد: مين يمسك الجوال الحين (تطلع شاشة التغطية قبله) ورسالتها |
| `canAct(d, priv)` | ← `true/false` | شرط زيادة على «دورك» |
| `host(d)` | ← `d` أو `null` | يمشّي اللعبة من جهاز واحد (الجوال، أو صاحب الغرفة أونلاين): ساعات، تخمينات مكتوبة، أحداث. ينادى كل 400ms |
| `after(d, ctx)` | | بعد كل رسمة (حركات يدوية، أصوات) |
| `onSkip(nd, d)` | ← `d` | لما لاعب يطلع أو ينطرد وسط اللعبة |
| `outDone`, `noTurn` | | مقعد `out` يعني «خلص» مو «خسر»، أو ما فيه دور يتحدد في الشريط |
| `onDraft(k, v)` | | الكتابة في حقل `data-draft` |

### البوتات (ضد البوت)

| الحقل | الوصف |
|---|---|
| `bot(d, s, lv)` | ← الحالة الجديدة لدور البوت. `lv`: 1 سهل، 2 متوسط، 3 صعب. إذا رجّع `undefined` المحرك يجرب أزرار اللعبة (`botClick`) |
| `botPick(d, s, lv)` | ← اختيار البوت في جولة متزامنة |
| `botDelay(d, s, lv)` | كم يفكر (الافتراضي 1.3 أو 1 أو 0.8 ثانية حسب المستوى، وزيادة عشوائية) |
| `botSee(nd)` / `botEval(nd, s)` | البوت يتذكر اللي شافه، وتقييم الوضع لـ `botGreedy` |

البوت يفكر على نسخة فاضية من واجهة الجوال (`botUI`)، فما يلمس كتابة الإنسان ولا اختياره. وفي الألعاب السرية البوت يقرا بس اللي يشوفه مقعده.

### الجولات المتزامنة (اختيارات سرية بنفس الوقت)

| الحقل | الوصف |
|---|---|
| `resolve(d, picks)` | ← الحالة بعد ما يختار الكل. `picks[s]` اختيار كل مقعد (`null` لو ما اختار أو طلع) |
| `simulNow(d)` | اللعبة تخلط الأدوار والجولات المتزامنة: هل المرحلة الحالية متزامنة؟ |
| `privInit(d, role)` / `privStale(d, p, role)` | الجزء الخاص الأول لكل لاعب (يسويه الجوال أو صاحب الغرفة)، ومتى يتجدد |
| `privOk(d, role, old, p)` | صاحب الغرفة يتأكد إن الجزء الخاص اللي أرسله اللاعب مسموح |

كل مقعد يحط `{rd, pick}` في جزءه الخاص (`simulPick`)، ولما يختار الكل يشتغل `resolve` مرة وحدة. `NOPICK` (`'~'`) يعني «اختار ما يجاوب».

### الأسرار أونلاين

| الحقل | الوصف |
|---|---|
| `hide: {seat:[…], all:[…], open(d)}` | حقول في `d`: `seat` كل مقعد يشوف خانته بس من المصفوفة، و`all` مخفية عن الكل. القيمة المخفية تحافظ على شكلها (5 ورقات تبقى 5، بس كلها `?`). كله ينكشف لما تخلص الجولة، أو لما `open(d)` |
| `mask(d, seat)` | بدل `hide`: اللعبة ترجع بنفسها اللي يشوفه المقعد (−1 = اللي بدون مقعد، يعني الكل) |
| `privShow(d, seat, role, p, own)` | وش يشوف المقعد `seat` من الجزء الخاص لـ `role` (الافتراضي: صاحبه يشوفه كامل، والباقين «اختار» بس) |
| `net: {host:[…], local:[…], ui:[…]}` | ضغطات تحتاج الحالة المخفية يلعبها صاحب الغرفة (`host`)، وضغطات واجهة بحتة تصير على الجوال (`local`)، ومفاتيح واجهة زيادة تنرسل مع الضغطة (`ui`) |
| `selfPub` | صاحب الجزء الخاص ينشره بنفسه في رسالته (رسم، كتابة)، وصاحب الغرفة يحط بداله `'@'` |
| `redeal(d)` | إذا طلع صاحب الغرفة وسط جولة سرية وما فيه نسخة احتياطية، اللي يستلم يعيد توزيع الجولة بهالدالة (وإلا جولة جديدة) |

أي لعبة فيها `hide` أو `mask` أو `privShow` أو `net` تعتبر **سرية** (`isSecretG`). فيها اللاعب ما يرسل حالة جديدة، يرسل **ضغطته**، وصاحب الغرفة يشغلها على الحالة الكاملة.

### مفاتيح محجوزة في `d`

المحرك يقرا ويتحقق من هذي المفاتيح، **فلا تستخدمها لشي ثاني** (لعبة استخدمت `wt` لاتجاه الريح وخرّبت الأونلاين):

| المفتاح | المعنى |
|---|---|
| `pl` | الأدوار (الألوان) المشاركة بالترتيب: المقعد `s` = `pl[s]` |
| `out` | نص `0`/`1` لكل مقعد: `1` طلع (أو خلص مع `outDone`) |
| `turn` | مقعد الدور الحالي |
| `win` | رقم مقعد الفايز، أو `'d'` للتعادل، أو `null` |
| `wins` | كل المقاعد الفايزة (فريق، أو أكثر من واحد) |
| `mw` | الدور اللي فاز بالمباراة (يحطه المحرك لما يوصل أحد لعدد الانتصارات) |
| `gid` | معرّف الجولة (يتغير كل جولة) |
| `st` | مقعد بداية الجولة (`newRound` يزيده واحد) |
| `tm` | فريق كل مقعد (0 إلى 3) |
| `wt` | الفريق الفايز |
| `wpts` | كم نقطة جلسة للفوز (الافتراضي 1) |
| `dsc` | نقاط الجلسة اللي تحركها اللعبة بنفسها |

**`d.dsc`:** مصفوفة رقم صحيح لكل مقعد (بين −1000 و1000). تنحط مع `win` في آخر الجولة، والمحرك يضيفها لنقاط الجلسة **مرة وحدة**، وما يخلي مجموع أي لاعب ينزل تحت الصفر. اللعبة اللي تستخدمها ما ينطبق عليها «المباراة تنتهي عند N انتصارات». تستخدمها «غميضة الحارة» (+15 و−15 و+20) و«طاق طاق طاقية».

## 3. الرسم: `render` و`morph` و`holdRender`

- **`render()`** في `core.js` يبني HTML الشاشة كاملة كنص، وبعدين **`morph`** يقارنه بالموجود ويغيّر اللي تغيّر بس. لذلك الصفحة ما تنط، والكتابة ما تضيع، والتركيز يبقى.
  - العناصر اللي لها `id` أو `data-k` تنطابق بالمعرّف.
  - إذا الـ HTML ما تغيّر، الصفحة ما تنلمس أبد (نبضات الأونلاين ما تكلف شي).
  - الشاشة الجديدة تدخل بحركة مرة وحدة (`scr-in`)، والتغييرات بعدها بدون حركة.
- **`S.holdRender = true`:** اللعبة تحرك الشاشة بيدها (مثل حبة تمشي خانة خانة)، والمحرك ما يرسم فوقها.
  - إذا جت رسمة بنفس الشاشة، تتأجل (`renderPending`).
  - أول رسمة حقيقية بعدها ترسم كل شي من جديد حتى لو الـ HTML نفسه.
  - إذا تغيّرت الشاشة (لعبة ثانية، رجوع)، الحجز ينفك لحاله.
- **الأمان:** النصوص اللي من اللاعبين تنعرض مهرّبة (`escH`). وأي نص في الحالة يجي من جهاز ثاني ينظّف (`cleanStr`)، فما يبقى فيه إلا وسوم بسيطة تكتبها الألعاب نفسها (`b`, `small`, `span`، بألوان وأصناف محددة).

## 4. المحرك أونلاين (`net.js` و`views.js` و`seal.js`)

### الفكرة

- **صاحب الغرفة يمشّي اللعبة:** عنده الحالة كاملة، والأجزاء الخاصة لكل اللاعبين.
- **الباقين يرسلون «نوايا»** (حركات) مشفّرة له. هو يلعبها بالترتيب، ويرد على كل مرسل، وينشر الحالة.
- **كل جهاز ينشر «حضوره»** (presence): رسالة JSON واحدة يحدّثها، والخادم يوصلها للكل.

### المفاتيح والتشفير

- كل جهاز عنده **زوج مفاتيح ECDH P-256** (`seal.js`)، محفوظ في `alaabna.key`. في claude.ai، اللي يمنع التخزين، يعيش مع الصفحة بس.
- **المفتاح العام `k` هو هوية الجهاز**، و`fp` (12 حرف منه) اسمه بالغرفة.
- المقاعد مربوطة بالمفاتيح (`S.ids[role] = fp`)، فاللي يطلع ويرجع ياخذ نفس اللون ونفس النقاط، والطرد يثبت عليه.
- **بين أي جهازين** فيه سر مشترك (ECDH)، ومنه مفتاح **AES-GCM 256**. كل رسالة `iv.ciphertext` بـ IV جديد (12 بايت)، ومع «بيانات إضافية» (AAD) تربطها بالغرفة ونوعها:

  | AAD | نوع الرسالة |
  |---|---|
  | `'q'+code` | نوايا اللاعب لصاحب الغرفة |
  | `'v'+code+…` | نسخة اللاعب من صاحب الغرفة |
  | `'b'+code` | النسخة الاحتياطية |

### وش ينشر صاحب الغرفة

`{v: NETV, id, k, n, ch, hb, h, g, s, d, sc, cfg, ids, pp, vw, bk, ack}`

| الحقل | المعنى |
|---|---|
| `h` | الحقبة (epoch): تزيد كل ما تغيّر صاحب الغرفة |
| `g`, `s` | اللعبة، ورقم الحالة |
| `d` | **النسخة العامة** من الحالة (`viewOf(G, d, -1)`): الأسرار فيها مخفية |
| `pp` | الأجزاء الخاصة كما يشوفها الكل (علامة «اختار» بس) |
| `vw[fp]` | **نسخة مختومة لكل جهاز:** فرق نسخته عن العامة (`dPatch`) وأجزاءه الخاصة، مشفّرة له. والـ AAD فيها كل الحقول العامة بشكل ثابت (`hostAad`)، فمفتاح منسوخ ما يقدر يغيّر أي حقل عام. الجهاز يعتمد رسالة صاحب الغرفة بس إذا نسخته انفتحت بمفتاحه، و`hb` أحدث من آخر وحدة (`verifyHost`) |
| `bk` | نسخة احتياطية كاملة مختومة للاعب اللي بيستلم إذا طلع صاحب الغرفة |
| `ack[fp]` | الرد على نوايا كل لاعب |

جهاز صاحب الغرفة نفسه يشوف كل شي، فالأفضل يكون شخص تثقون فيه.

### النوايا (intents)

كل لاعب ينشر طابور `q` (6 كحد أقصى، `QMAX`)، وكل عنصر `{n, c}`: `n` رقم متزايد، و`c` النية مختومة لصاحب الغرفة.

| النوع | متى | وش يسوي صاحب الغرفة |
|---|---|---|
| `nd` | حركة في لعبة **عامة** | يرسل التغيير من الحالة اللي انلعبت عليها (`dp`، مع `base` و`dep`). الحركة تطلع عند اللاعب على طول. صاحب الغرفة يطبّق التغيير ويتحقق (`validateProposal`): نفس الجولة ونفس اللاعبين، ما أحد يرجع، الجولة ما خلصت، واللاعب يقدر يلعب الحين (دوره، أو اختياره في جولة متزامنة، أو الحركات المسموحة برّا الدور `OFFTURN`) |
| `ck` | ضغطة في لعبة **سرية** | يرسل الضغطة (`a`, `i`) وحالة واجهته (`ui`). صاحب الغرفة يشغلها في «صندوق» باسم اللاعب (`sandboxClick`)، ويرجع له التنبيهات وتغييرات الواجهة. اللاعب يجرب الضغطة عنده أول، وإذا ما تحتاج سر تنحل عنده |
| `pv` | الجزء الخاص (اختيار، كتابة، رسم) | يرسل الجزء كامل، والأحدث يستبدل اللي ينتظر. صاحب الغرفة يتأكد إنه للجولة الحالية، وما يغيّر اختيار انحسم، ويمر على `privOk` |
| `skip` | تخطّي لاعب غايب | |
| `new` | جولة جديدة | |
| `game` | اختيار لعبة (إذا «الكل يختار») | |

### الردود (acks)

- صاحب الغرفة يرد على كل لاعب بـ `ack[fp] = {n, x?, t?, u?}`:

  | الحقل | المعنى |
  |---|---|
  | `n` | آخر نية انحسبت |
  | `x` | سبب الرفض: `stale`، `bad`، `secret`، `pick`، `seat`… |
  | `t` | تنبيهات |
  | `u` | تغييرات واجهة |
- الرد يبقى لين يختفي من طابور اللاعب.
- **الرفض:** يطلع للاعب «ما انحسبت حركتك»، وحركته العامة تنشال.
- **ما وصل رد خلال 6 ثواني** (`PEND_MS`): النية تنشال، ويطلع «ما وصلت حركتك، جرّب مرة ثانية».

### النبض والاستلام (heartbeat و takeover)

- **النبض:**
  - كل جهاز ينشر كل 4 ثواني على الأقل (`HB_MS`)، ومعه `hb` (ساعته).
  - الجهاز اللي ما تغيّر حضوره 12 ثانية (`HB_DEAD`) ينحسب نايم.
  - الصفحة اللي وقفت فترة (الجوال نام) تعتبر نفسها كانت مقطوعة.
- **اللاعب اللي ينقطع:**
  - ينتظرونه 15 ثانية (`GRACE`)، وبعدها يقدرون «يتخطّونه».
  - مقعده ينحجز له 3 دقايق (`HOLD`)، إلا إذا هو داخل جولة شغالة.
- **إذا طلع صاحب الغرفة،** اللي بعده يستلم:
  - **الترتيب:** اللاعبين الصاحيين حسب اللون، وما يستلم مفتاح صاحب الغرفة القديم أبد.
  - **متى:** بعد 4 ثواني (`TAKE_FAST`)، أو 15 ثانية (`TAKE_SLOW`) إذا اللعبة سرية وما عنده نسخة احتياطية، أو 1.5 ثانية (`RESUME_WAIT`) إذا هو نفسه صاحب الغرفة راجع. وإذا الأول ما استلم خلال 6 ثواني (`TAKE_NEXT`)، يستلم اللي بعده.
  - **طرق الاستلام:**
    - `resume`: صاحب الغرفة رجع بحالته المحفوظة؛
    - `bk`: من النسخة الاحتياطية المختومة؛
    - `public`: اللعبة عامة، يكمل من الحالة العامة؛
    - `redeal`: لعبة سرية بدون نسخة، يعيد توزيع الجولة (`G.redeal`) أو يبدأ جولة جديدة («صاحب الغرفة طلع، بدأنا الجولة من جديد»).
- **صاحبين للغرفة بنفس الوقت:** الأعلى حقبة يفوز، وبعدها الأقل لون، وبعدها الأقل مفتاح. صاحب الغرفة الموجود ما ينشال إلا إذا كان مقطوع قريب.
- **نفس المتصفح بتبويبين:** الغرفة تبقى بالتبويب الأول (`alaabna.tabs`).

### `NETV`

رقم نسخة البروتوكول (الحين **3**). الجهاز اللي نسخته أقدم يتجاهلونه، وصاحب الغرفة يكتب في المحادثة «فيه جهاز بنسخة قديمة». والجهاز اللي يلقى صاحب غرفة بنسخة أحدث يطلع له «حدّث التطبيق». **أي تغيير يكسر التوافق بين الأجهزة يرفع `NETV`.**

### حدود المعدل والحجم

| الحد | القيمة |
|---|---|
| النشر | بعد لحظة هدوء ينطلق على طول، ووقت الزحمة (رسم، كتابة) يتجمع كل 40ms (`PUB_MS`) |
| رسائل الجهاز | 100 رسالة كل 10 ثواني كحد أقصى (`RATE_N`)، تحت حد الخادم 120، والجهاز ينتظر بدل ما ينقطع |
| المحادثة | 160 حرف للرسالة. 6 رسائل كل 10 ثواني من الجهاز، والمستقبل ياخذ 10 كحد أقصى من كل جهاز |
| النية | 60,000 حرف مختوم كحد أقصى، و`nd` 40,000، و`pv` 16 ك.ب، والواجهة 2 ك.ب |
| غرف claude.ai | تقريبًا 4 ك.ب لكل لاعب: تنشال النسخة الاحتياطية أول، ثم أقدم رسائل المحادثة |

## 5. خادم الغرف (`worker/index.js`)

Cloudflare Worker يقدّم ملفات `public/` (`ASSETS`)، وكل رمز غرفة له **Durable Object** خاص فيه (`Room`). **الخادم ما يحفظ شي عن اللعبة**: كل جهاز يرسل حضوره، والغرفة توصله للباقين.

| الشي | القيمة والسلوك |
|---|---|
| مسار الغرفة | `/ws/g-<4 إلى 6 حروف وأرقام>` بس، وغيره 404 |
| `?c=1` (إنشاء) | إذا الغرفة مفتوحة أو فيها أحد يرد `taken` (4009)، والتطبيق يختار رمز ثاني (5 محاولات). غير كذا تنفتح |
| `?j=1` (دخول) | إذا الغرفة مو مفتوحة يرد `noroom` (4004) قبل الدخول |
| بدون الاثنين | نسخ التطبيق القديمة: تفتح الغرفة مثل قبل |
| `ROOM_KEEP` | 12 ساعة: الغرفة الفاضية تبقى مفتوحة عشان اللاعبين يرجعون، وبعدها تنمسح (alarm) |
| السعة | 16 اتصال، وبعدها `full` (4001) |
| `MAX_MSG` | 32,768 حرف للرسالة، والأكبر ينرمى |
| `RATE_MAX` | 120 رسالة كل 10 ثواني (`RATE_MS`)، واللي يزيد ينقطع (1008) ويطلع للباقين كأنه طلع |
| الرسائل | `hello` (معرّفك والموجودين)، `join`، `leave`، `p` (حضور)، و`ping`/`pong` |
| `/version.json` | يقدّمه الـ Worker بنفسه مع `Access-Control-Allow-Origin: *` و`no-store`، عشان التطبيق يقراه |

**جهة التطبيق** (`transport-ws.js`):
- **الاتصال:** `ping` كل 20 ثانية. الاتصال اللي ما يسمع شي 35 ثانية ينحسب ميت، ويرجع يتصل بعد 1.5 ثم 3 ثم 6 ثواني… لين 30 ثانية.
- **أول ما يرجع النت أو التطبيق:** يتأكد على طول.
- **الحالات للمحرك:** `lost` و`back` و`full` و`bye`.
- **وين يتصل:** داخل تطبيق أندرويد الغرف تروح لعنوان Cloudflare الثابت. في المتصفح تروح لنفس العنوان اللي انفتحت منه الصفحة (`workers.dev` أو `localhost`؛ الدومين الخاص ينضاف في `WSROOM.available`، انظر [SETUP.md](../SETUP.md)).

## 6. الغرف القريبة بدون نت (أندرويد)

- **الجهة الأصلية** (`app/android/app/src/main/java/com/alaabna/games/NearbyPlugin.java`):
  - تستخدم Google Nearby Connections بشكل نجمة (`P2P_STAR`): جوال واحد يعلن الغرفة ويصير مركزها، والباقين يلقونها ويتصلون فيها. Nearby يختار البلوتوث أو الواي فاي المباشر لحاله.
  - الطرفين يقبلون الاتصال، وبعدها يرسلون نصوص JSON صغيرة، نفس رسائل الغرف أونلاين.
  - **الصلاحيات حسب أندرويد:**
    - 7 إلى 11: الموقع؛
    - 12: البلوتوث (الأجهزة القريبة) والموقع الدقيق؛
    - 13 وفوق: البلوتوث والواي فاي القريب، بدون موقع.
  - فيه فحص لحالة الجوال (خدمات Google، البلوتوث، الموقع) وأزرار تفتح الإعدادات اللازمة.
  - إذا انقفل التطبيق يبلّغ الباقين على طول.
- **جهة JavaScript** (`public/js/transport-near.js`، `NEARROOM`):
  - تعطي المحرك **نفس واجهة الغرف** (`join` و`presence` و`onPeers` و`leave`). المركز يوصل حضور كل جوال للباقين، فـ `net.js` يشتغل بدون أي تغيير.
  - الرسالة الأكبر من 30,000 بايت تتقطع قطع وتتجمع (`LIM`).
  - **الانقطاع:** يعيد المحاولة كل 4 ثواني، ويدوّر من جديد كل 12 ثانية، ويوقف بعد دقيقة (`gone`). وإذا صاحب الغرفة قفلها يوصل `bye`.
  - أخطاء النظام تتحول لجملة عربية قصيرة (`nearErr` في `core.js`)، والتفاصيل التقنية بس بالضغط الطويل على العنوان.

## 7. غرف claude.ai

- **إذا التطبيق انفتح داخل claude.ai** (`window.claude.use` موجود)، `getRoom()` في `core.js` يطلب غرفة من Claude (`window.claude.use('room')`) بدل Cloudflare.
- **نفس الواجهة:** الغرفة تعطي `join` و`presence` و`onPeers`، فالمحرك نفسه يشتغل.
- **الفروق:**
  - **الحجم أصغر** (تقريبًا 4 ك.ب لكل لاعب، `nr.max`): `doPublish` يشيل النسخة الاحتياطية أول، ثم أقدم سطور المحادثة. والألعاب اللي فيها `selfPub` تنشر علامة `'@'` بس.
  - **التخزين ممنوع،** فمفتاح الجهاز يعيش مع الصفحة بس.
  - **المشاكل:** الغرفة تبلّغ عن المشاكل بس (تنبيه)، وما تقول «خلص».
  - **ما فيه `_headers`:** claude.ai وتطبيق أندرويد ما يقرون `_headers`، فما فيه `meta` لـ CSP في `index.html`.

## 8. الحالة على الجوال (`localStorage`)

| المفتاح | وش فيه |
|---|---|
| `alaabna.v4` | آخر غرفة: الرمز، والحالة، والمقاعد، والحقبة. لزر «ارجع لغرفتك» |
| `alaabna.local` | إعداد اللعب على جوال واحد: العدد، الأسماء، البوتات، الفرق |
| `alaabna.lgame` | اللعبة اللي ما خلصت على الجوال («كمّل اللعبة») |
| `alaabna.name`, `alaabna.av` | الاسم والصورة |
| `alaabna.recent`, `alaabna.fav`, `alaabna.stats`, `alaabna.meta` | آخر الألعاب، والمفضلة، والإحصائيات، وما تعرضه الصفحة الرئيسية قبل تحميل الألعاب |
| `alaabna.mute`, `alaabna.lite`, `alaabna.hide` | كتم الصوت، والوضع الخفيف، واللاعبين اللي مخفية رسائلهم |

| `alaabna.tabs` | التبويبات المفتوحة على غرفة |
| `alaabna.here` (`sessionStorage`) | وين كان هالتبويب، عشان تحديث الصفحة يرجعه لنفس الشاشة |

كل قراءة وكتابة داخل `try/catch` (`lsGet` و`lsSet`)، والتطبيق يشتغل حتى لو التخزين ممنوع.
